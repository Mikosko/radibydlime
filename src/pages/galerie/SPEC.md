# Gallery pages

`/galerie/` is the album index, replacing the unimplemented Zápisky destination. It queries published [albums](../../content/albums/SPEC.md) and shows a vertical list of album rows with title, description and derived photo count beside a large cover and an asymmetric preview mosaic. Up to five distinct photos follow authored order; a remaining-count tile shows only additional photos. Three deterministic compositions vary the rhythm without shuffling content. Rows contain no botanical ornament. Mobile and tablet use a single bordered card with photography first and description plus a right-aligned album link below. The cover shows the photo count and title over a dark gradient with light text and a text shadow; its publication badge stays at the top left. Desktop retains copy on the left and the mosaic on the right. Only the breakpoint-appropriate title is visible; each collage is one accessible album link. Each card opens `/galerie/<slug>/`; the index has no image dialogs. An empty state handles no published albums.

Album detail pages use the existing ArticleGallery grid and modal viewer with captions, chevrons, keyboard navigation and native dialog focus handling. Both top and bottom link back to all albums, using ReturnToList to preserve native history scroll restoration when arriving from the index. An optional related published Project links by resolved canonical ID. Gallery remains current in primary navigation on both index and detail pages.

Reuse the shared shell, local typography and restrained botanicals. No new runtime service or gallery framework is introduced; remote catalog images are never fetched at build time. Initial albums contain sample photos. Pagination is deferred until the album count needs it.

Cover dates reuse CalendarBadge with UTC publication dates and the accessible “Zveřejněno” prefix.
